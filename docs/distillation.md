# exifframe.org 功能蒸馏报告

> 抓取时间：2026-11-02 01:04 (GMT+8) · 工具：Scrapling 0.5 `extract get --ai-targeted`（HTTP，未触发反爬，无 JS 挑战）
> 抓取页面：`/zh`、`/zh/templates`、`/zh/editor`（另取其两份模板预览图做像素级版式测量）
> 目的：把站点能力拆成「可实现的规格」，作为自托管容器工具 **viaEXIF** 的需求基线。本文只记录功能与参数，不复用其代码、文案与商标图元。

## 1. 站点地图与技术判定

| 路由 | 作用 | 蒸馏价值 |
|---|---|---|
| `/zh` | 落地页：Hero + 上传入口 + 功能特点 + 品牌墙 + FAQ | 需求口径（免费、免注册、浏览器本地处理） |
| `/zh/templates` | 模板陈列 + 三步流程 | 模板只有 2 个 |

技术判定：Nuxt 产出（资源在 `/_nuxt/*`），编辑器是**纯前端 Canvas 渲染**——FAQ 明确「所有图片处理都在您的浏览器本地完成」。`<script type="application/ld+json">` 声明为 `WebApplication`。

## 3. 元素清单（`/zh/editor` 实测 DOM）

### 3.1 模板选择（2 张卡片）

| id | 名称 | 描述 | 卡片元素 |
|---|---|---|---|

### 3.2 EXIF 信息区

| 控件 | 类型 | 实测属性 |
|---|---|---|
| 相机品牌 | 下拉（缩略图 + 名称） | 32 项，首项默认 Canon |
| 相机型号 | `text` | placeholder `EOS R5` |
| 焦距 | `text` | placeholder `85mm` |
| 光圈 | `text` | placeholder `f/2.8` |

> 原站给的是**自由文本**，不是数值控件——说明用户可能填 `24-70mm`、`f/1.4`、`1/2s` 这类非标准串。本实现照此保留文本输入，只在自动填充时做格式化。

### 3.3 水印设置（2 个 `range`）

| 名称 | 提示文案 | min | max | step | default |

| 品牌图片大小 | 调节品牌图片相对于白条高度的大小比例 | 0.15 | 0.60 | 0.05 | 0.30 |

### 3.4 导出区

- `下载到本地`（主按钮）
- `生成分享链接`（次按钮）
- 文件输入：`accept="image/jpeg,image/png,image/webp"`，两个 hidden input（首页 + 编辑器各一）

## 4. 版式规格还原

用其两张模板预览图（`photo1.webp` 3200×2424、`photo2.webp` 1920×1160）反推比例，全部以**图片宽度 W** 为基准。

### 4.1 经典（classic）

```
┌──────────────────────────────┐
│            照片              │  ← 原图等比铺满，不裁切
├──────────────────────────────┤
│ 机型(粗)          BRAND │ 参数 │  ← 白条，高度 = W × barRatio
│ 时间(灰)                      │
└──────────────────────────────┘
```

| 量 | 比例（× 白条高 barH） | 依据 |
|---|---|---|
| 画布高度 | 原图 H + barH | 竖向扩张，不裁图 |
| 左右内边距 | W × 0.02 | 实测 X-T4 距左边 ≈ 2% W |
| 机型字号 / 字重 | 0.26 barH / 600 | "X-T4" 字面高对齐 |
| 时间字号 / 颜色 | 0.155 barH / `#6B7280` | 次级灰 |
| 参数行字号 | 0.23 barH | 与右侧基线一致 |
| 机型基线 / 时间基线 | 0.45 / 0.82 barH | 两行左对齐堆叠 |
| 品牌 logo 高度 | 0.3333 barH × (brandRatio/0.30)，即白条高度的 1/3 | 滑杆直接缩放该值，宽度按各 logo 的宽高比等比缩放 |
| 分隔线 | 宽 0.012 barH（≥1px），高 0.46 barH，色 `#D1D5DB` | 竖线居中 |
| 元素间距 | 0.13 barH | 品牌名与竖线、竖线与参数等距 |

顺序（左→右）：`机型/时间` … `品牌 logo` `│` `焦距 光圈 快门 ISO`。
防溢出：右组先按 58% W 上限等比缩放，左组取剩余宽度，超出则 `fitFont` 降档（下限 62%）。

### 4.2 模糊（blur）

```
┌──────────────────────────────┐
│ ░░░ 模糊放大的原图（压暗 22%）░░ │
│   ┌────────────────────┐     │
│   │   原图（直角内嵌）    │     │
│   └────────────────────┘     │
│        BRAND 机型            │  ← 白字 + 阴影
│      焦距 光圈 快门 ISO       │
└──────────────────────────────┘
```

| 量 | 比例（× W） |
|---|---|
| 画布 | 宽 W；高 = padTop + 内嵌图高 + 底部文案条（随照片比例伸缩） |
| 内嵌图左右边距 | 0.062 W |
| 内嵌图上边距 | 0.030 W |
| 内嵌图尺寸 | 宽 0.876 W，高按**原图宽高比**换算 —— 整张照片原样显示，不裁切 |
| 圆角 | 滑杆控制，默认 0（直角）；0–0.05 W（界面按 1200px 宽基准显示 0–60px） |
| 背景模糊半径 | 0.020 W（高斯） |
| 背景压暗 | 黑 22% 叠加 |
| 文案字号 | 0.0165 W |
| 第二行基线 | 距底 0.036 W（自下而上定位） |
| 两行间距 | 1.35 × 字号 |
| 品牌 logo 高度 | 1.15 × 字号 × (brandRatio/0.30) |
| 品牌与机型间距 | 0.55 × 字号 |

文案画在背景上而非照片上，因此白光字 + 40% 黑阴影保证可读。

## 5. EXIF → 显示文案规则

| 显示项 | EXIF 标签 | 格式规则 |
|---|---|---|
| 相机品牌 | `Make`(0x010F) + `Model` | 归一化后匹配 34 品牌表；无命中则用机型串推断；仍无则不显示 logo |
| 相机型号 | `Model`(0x0110) | 原样，去尾零字节 |
| 焦距 | `FocalLength`(0x920A) | 四舍五入取整 + `mm` |
| 光圈 | `FNumber`(0x829D) | `f/` + 一位小数（`f/2` 不写 `f/2.0`） |
| 快门 | `ExposureTime`(0x829A) | <1s → `1/N s`，并对齐 1/3 档阶梯（1/8000…1/2）；≥1s → `N s` |
| ISO | `ISOSpeedRatings`(0x8827) / `ISOSpeed`(0x8833) | `ISO` + 整数 |
| 拍摄时间 | `DateTimeOriginal`(0x9003) → 兜底 `DateTime`(0x0132) | `2024:05:16 12:33:44` → `2024-05-16 12:33` |

容器解析：JPEG 扫 `APP1` 找 `Exif\0\0`；PNG 找 `eXIf` chunk；WebP 找 RIFF `EXIF` chunk —— 三者载荷同为 TIFF/IFD，一个解析器覆盖。

## 6. 原站的缺口 → 本实现的取舍

| 原站问题 | 本实现 |
|---|---|
| 明确不支持批量 | ZIP store-only 打包，前端逐张渲染，内存安全（导出时才解码原图） |
| 分享链接依赖其公共服务 | 自托管 `/s/{id}` + TTL 自动清理，落 own volume |
| 品牌字标用官方 SVG（商标资源） | 采用**本地 SVG logo 图片**（`web/assets/brands/`），viewBox 统一裁到墨迹外框后再按比例缩放，因此同高度即同视觉高度；单色 logo 在深色模板重绘为白，彩色 logo 保留原色。商标归各品牌所有，仅用于标识拍摄设备 |
| 无 API | `/api/config` 作为唯一版式/品牌配置源，`/api/share`、`/s/{id}` 可脚本调用 |
| 无参数校验 | 后端 MIME 白名单 + 体积上限；前端 `MAX_FILES`、字体自适应降档 |

## 8. 相机原生格式的实现取舍

| 决策点 | 选择 | 理由 |
|---|---|---|
| 判定依据 | 文件头魔数（`ftyp` brand / TIFF 头 / RAF / X3F / ORF / IIQ / MRW） | 相机文件在浏览器里 `File.type` 常为空串，扩展名也常被改坏；魔数不会撒谎 |
| HEIC 解码 | pillow-heif（libheif 随 wheel 分发） | 一个 wheel 同时覆盖 HEIC / HEIF / AVIF，含 EXIF 与方向 |
| RAW 解码 | rawpy（libraw 随 wheel 分发） | camera white balance + AHD 去马赛克 + sRGB 输出，接近厂商直出观感；纯 Python 无法解 CFA |
| RAW EXIF | exifread | RAW 是 TIFF 容器，exifread 直接读 IFD0/ExifIFD，不必等解码 |
| 像素回传 | 两段式：`POST /api/decode` 拿 token，`GET /api/decode/{token}` 拿 JPEG | 60MP RAW 转出的 JPEG 有 10–20MB，塞进 JSON base64 会膨胀 33% 且卡住主线程 |
| 缓存 | 进程内 `FrameCache`，TTL 15 分钟 / 512MB | 解码帧是中间产物，不该进 `/data`，也不该被分享链接的生命周期绑住 |
| 导出分辨率 | 解码后最长边上限 12000px（可配） | 一亿像素的 DNG 全解会让 4GB 容器 OOM；12000px 已远超水印所需 |
| 实况照片 | 识别 + 打包，不伪造配对 | 真 Live Photo 需要把 content identifier 写回 HEIC 容器，Canvas 做不到；UI 明说「素材包」而不是「实况照片」 |
| 隐私边界 | JPG/PNG/WEBP 完全本地；HEIC/RAW 上传一次、不落盘 | README 与界面文案都写清楚，不假装「全部本地」 |
